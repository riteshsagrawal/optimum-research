## vLLM Logprobs and Token Generation Breakdown

### Overview

This discussion analyzes how to query an OpenAI-compatible endpoint (such as [vLLM](https://github.com/vllm-project/vllm)) to inspect generation confidence and token-level log probabilities (`logprobs`). It covers why prompt-like tokens appear in the output distribution and examines how input log probabilities operate internally.

---

### 1. Code Implementation & Explanation

The Python snippet queries a local server running an OpenAI-compatible API, requests log probabilities for the response, and formats the output into an ASCII probability bar chart:

```python
import math
from openai import OpenAI

# Initialize client pointing to local vLLM endpoint
client = OpenAI(base_url="http://localhost:8000/v1", api_key="unused")

resp = client.chat.completions.create(
    model=MODEL,
    messages=[{"role": "user", "content": "The capital of France is"}],
    max_tokens=15,
    temperature=0.0,
    logprobs=True,
    top_logprobs=5,
    extra_body={"chat_template_kwargs": {"enable_thinking": False}},
)

print(f"Response: {resp.choices[0].message.content.strip()}\n")
print("Token-by-token probabilities:\n")

for tok in resp.choices[0].logprobs.content[:8]:
    print(f"  Chosen: '{tok.token}'  (logprob {tok.logprob:.2f})")
    if tok.top_logprobs:
        for alt in tok.top_logprobs[:5]:
            pct = math.exp(alt.logprob) * 100
            bar = "\u2588" * min(20, max(1, int(pct / 5)))
            print(f"    {pct:5.1f}%  {bar}  '{alt.token}'")
    print()

```

#### Key API Parameters

* **`model=MODEL`**: Specifies the loaded model (e.g., Qwen3-0.6B).
* **`messages`**: Input chat conversation.
* **`temperature=0.0`**: Deterministic/greedy decoding; always selects the argmax logit.
* **`max_tokens=15`**: Caps the generation phase at 15 new tokens.
* **`logprobs=True` & `top_logprobs=5**`: Returns log probability values ($\ln P$) along with the top 5 alternative tokens considered at each generation step.
* **`extra_body={"chat_template_kwargs": {"enable_thinking": False}}`**: Custom Jinja template parameter used to turn off internal chain-of-thought `<think>` blocks.

#### Probability Formatting Logic

* **Logprob to Linear Percentage**: $P = e^{\text{logprob}} \times 100$.
* **Visual Bar Representation**: Uses Unicode block characters (`█`), where each block represents roughly a 5% slice of probability up to a maximum width of 20 blocks.

### 2. Output Analysis: Why Did the Model Output Prompt Tokens?

#### Observation

The returned sequence begins with:

```text
Chosen: 'The'      (logprob -0.00)
Chosen: ' capital'  (logprob -0.00)
Chosen: ' of'       (logprob -0.00)
Chosen: ' France'   (logprob -0.00)
Chosen: ' is'       (logprob -0.00)
Chosen: ' **'       (logprob -0.08)
Chosen: 'Paris'     (logprob -0.08)
Chosen: '**'        (logprob -0.04)

```

#### Cause

These are **completion tokens**, not input prompt tokens:

* The user prompt was `"The capital of France is"`.
* In chat models, an incomplete sentence given as a user turn is often answered by echoing the setup as a complete declarative statement:

$$\text{Completion: } \text{"The capital of France is \textbf{Paris}."}$$


* Because `resp.choices[0].logprobs.content` only holds newly generated tokens, every token printed by the loop was generated by the model during the autoregressive decode phase.

### 3. Understanding Prompt Logprobs (Prefill Phase)

Inference engines like [vLLM](https://docs.vllm.ai/en/latest/) also support scoring input tokens directly via the `prompt_logprobs` parameter.

#### Mechanics

1. **Parallel Evaluation**: During the prefill stage, all input tokens pass through causal attention simultaneously.
2. **Next-Token Logits**: At token position $i$, the model computes a logit distribution for position $i+1$.
3. **Scoring Fixed Inputs**: The softmax function is applied over the vocabulary to determine the exact probability assigned to whichever token actually followed at position $i+1$ in the input prompt.

#### Practical Applications of Input Logprobs

* **Perplexity Evaluation**: Summing input token log probabilities calculates prompt perplexity:

$$\text{Perplexity} = \exp\left(-\frac{1}{N} \sum_{i=1}^{N} \ln P(w_i \mid w_{<i})\right)$$


* **Out-of-Distribution & Adversarial Detection**: Garbage text, jailbreak tokens (e.g., GCG suffixes), and corrupted prompts produce sharp drops in logprobs.
* **Discriminative Classification**: Evaluates relative probabilities of candidate continuations directly over fixed strings without running autoregressive decoding loops.
* **RAG Confidence Calibration**: Measures how naturally retrieved passages fit within the model's learned distribution given the user context.
