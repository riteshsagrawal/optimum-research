### Assistant

This code sends a chat completion request to a local vLLM server using the standard OpenAI Python client, measures the round-trip latency, and prints the generated response along with token usage statistics.

**Latency Tracking**

* `start = time.time()` records the timestamp right before sending the API request.
* `elapsed = time.time() - start` calculates the total wall-clock time in seconds taken by the server to process the prompt and return the completed response.

**API Request Parameters**

* **`model=MODEL`**: Specifies the model hosted on the vLLM server (in this notebook, `Qwen3-0.6B`).
* **`messages=[...]`**: The conversational payload formatted using standard chat roles. Here, a single `user` message asks: *"What is PagedAttention in one sentence?"*.
* **`max_tokens=80`**: Limits the generation length to at most 80 new tokens.
* **`temperature=0.7`**: Controls randomness. Values closer to 1 produce more creative or varied output, while values near 0 make it deterministic.
* **`top_p=0.8`**: Nucleus sampling cutoff. The model samples only from the smallest set of top tokens whose cumulative probability reaches 80%.
* **`extra_body={...}`**: Passes non-standard OpenAI arguments directly through to the vLLM backend:
* `"top_k": 20`: Restricts sampling to the top 20 highest-probability tokens at each generation step.
* `"chat_template_kwargs": {"enable_thinking": False}`: Disables the reasoning/chain-of-thought (`<think>...</think>`) mode supported by models like Qwen, keeping the response direct and short.



**Output Handling**

* **`resp.choices[0].message.content`**: Extracts the actual text response generated by the model.
* **`resp.usage`**: Accesses token metrics returned by the vLLM server:
* `prompt_tokens`: Number of tokens in the input prompt.
* `completion_tokens`: Number of tokens generated in the output.
* `total_tokens`: Sum of prompt and completion tokens.

### User

temperature, top_p and top_k all are used here. Explain in what order they are applied and how with example.

---

### Assistant

In inference engines like vLLM, sampling parameters are applied sequentially at each token generation step before the final token is sampled:

1. **Temperature** (reshapes the raw logit distribution)
2. **Top-K** (filters down to a fixed number of candidates)
3. **Top-P / Nucleus** (filters dynamically based on cumulative probability)

---

**Step-by-Step Execution Order**

* **Step 1: Temperature (`temperature = 0.7`)**
Raw model logits $z_i$ are scaled by dividing them by the temperature: $z_i' = \frac{z_i}{T}$. A softmax function is then applied to turn the scaled logits into a probability distribution. Because $T = 0.7 < 1.0$, the differences between logits become sharper, making higher-probability tokens more dominant while suppressing low-probability "noise."
* **Step 2: Top-K (`top_k = 20`)**
The engine sorts all tokens in the vocabulary by their post-temperature probability and keeps only the top $K$ (here, 20) tokens. All remaining tokens outside this top 20 are set to zero probability (or masked out).
* **Step 3: Top-P / Nucleus (`top_p = 0.8`)**
From the remaining 20 candidates, the engine computes running cumulative probabilities starting from the highest to the lowest. It truncates the list at the smallest set of tokens whose sum reaches or exceeds $p = 0.8$ (80%). The surviving tokens are then renormalized so their probabilities sum to 1.0, and the engine randomly draws the next token from this final subset.

---

**Concrete Example**

Suppose after processing a prompt, the model is about to generate the next token:

* **Raw state:** The vocabulary contains 100,000+ possible tokens.
* **After Temperature (0.7):** The distribution is sharpened. Suppose token A has 45%, token B has 25%, token C has 12%, token D has 8%, token E has 4%, and the remaining thousands share the last 6%.
* **After Top-K (20):** Only the 20 highest-probability tokens survive; everything ranked 21st to 100,000th is eliminated immediately.
* **After Top-P (0.8):**
* Token A (45%) $\rightarrow$ cumulative: 45%
* Token B (25%) $\rightarrow$ cumulative: 70%
* Token C (12%) $\rightarrow$ cumulative: 82% (threshold $\ge 80\%$ reached)
Tokens D through the 20th candidate are pruned away, even though they survived Top-K.


* **Final Selection:** Tokens A, B, and C are renormalized to sum to 100%, and one is sampled randomly according to its relative weight.

### User

how does renormalized probs are calulated in the above?

---

### Assistant

Renormalization rescales the probabilities of the surviving tokens so their sum equals 1.0 (or 100%), while keeping their relative ratios intact.

**Mathematical Formula**

If $S$ is the subset of tokens that survived both the Top-K and Top-P filtering steps, the new probability $P'(i)$ for each token $i \in S$ is computed as:

$$P'(i) = \frac{P(i)}{\sum_{j \in S} P(j)}$$

Where:

* $P(i)$ is the token's probability before truncation (after temperature scaling and initial softmax).
* $\sum_{j \in S} P(j)$ is the sum of probabilities of only the surviving tokens.

---

**Step-by-Step Calculation (Using the Previous Example)**

From the earlier example, the tokens surviving the 80% threshold were:

* Token A: $P(A) = 0.45$ (45%)
* Token B: $P(B) = 0.25$ (25%)
* Token C: $P(C) = 0.12$ (12%)

**1. Calculate the Normalization Constant ($Z$)**
Sum the probabilities of only these three tokens:


$$Z = 0.45 + 0.25 + 0.12 = 0.82$$

**2. Divide Each Token's Probability by $Z$**

* **Token A:**

$$P'(A) = \frac{0.45}{0.82} \approx 0.5488 \quad (\approx \mathbf{54.88\%})$$


* **Token B:**

$$P'(B) = \frac{0.25}{0.82} \approx 0.3049 \quad (\approx \mathbf{30.49\%})$$


* **Token C:**

$$P'(C) = \frac{0.12}{0.82} \approx 0.1463 \quad (\approx \mathbf{14.63\%})$$



**3. Verification**


$$0.5488 + 0.3049 + 0.1463 = 1.0000 \quad (100\%)$$

Their relative odds remain identical (for instance, Token A is still exactly $1.8\times$ more likely than Token B: $\frac{0.5488}{0.3049} = \frac{0.45}{0.25} = 1.8$), but the probability space is now valid for random sampling.
